# Guts & Bolts Debugging

Use this skill when diagnosing a broken project, script, playtest, or editor workflow.

1. Reproduce the issue or gather the exact error before changing code.
2. Inspect the relevant object, script, runtime output, and recent changes.
3. Separate observed facts from hypotheses. Do not treat a likely cause as confirmed.
4. Make one minimal, reversible change at a time.
5. Re-run the failing operation or playtest and inspect the new output.
6. If the issue remains, report what was tested and what evidence is still missing.
7. Preserve user work. Never delete or overwrite project content as speculative cleanup.
