Sysfix brings system information and troubleshooting tools together. Start with a quick health report, then dig into the area that needs attention.

01 / SYSTEM HEALTH

See the state of your machine.

Inspect CPU usage, physical memory, swap, mounted storage, running processes and available temperature readings. Find failed services, boot issues, USB devices and disk-health information where supported.

GET UP AND RUNNING

Start using Sysfix
in a few steps.

Sysfix targets modern Linux distributions and requires Python 3.10 or newer. The packaged release is the easiest way to get started.

01

DOWNLOAD

Choose your package.

Use the RPM package for Fedora-family distributions or the DEB package for Debian-family distributions.

Go to downloads ↗
02

INSTALL

Install the package.

Open a terminal in the folder where you downloaded the file and run the command for your distribution.

FEDORA / RPMsudo dnf install ./sysfix-ai-1.2.0-1.fc44.noarch.rpm
DEBIAN / UBUNTU / DEBsudo apt install ./sysfix-ai_1.2.0-1_all.deb
03

LAUNCH

Open Sysfix.

Launch the desktop app from your application menu or start it from a terminal.

TERMINAL MODEsysfix terminal
Prefer installing from source?

Clone the repository and install the Python package in editable mode. This is useful for development and testing.

$ git clone https://github.com/Guts-Bolts/Sysfix.git
$ cd Sysfix
$ pip install -e .

The repository's package metadata and README are the source of truth for dependencies and current installation requirements.

CONTROL STAYS WITH YOU

Diagnostics first.
Changes only with care.

Sysfix is designed to make system state easier to understand. A report is not permission to change your computer.

✓

Read-only health checks

The structured sysfix health report does not need root and does not change services, processes, files or kernel settings.

!

Review proposed actions

Read recommendations and understand their impact before running commands that change system state.

⌑

Some features need privileges

Security monitoring, hardware interfaces and advanced integrations may require root, extra packages or kernel support.

Current safety boundary

In the current stabilization build, autonomous repair execution is disabled. Advanced capabilities such as eBPF monitoring, malware analysis and micro-VM isolation are optional and should be treated as experimental until validated on the target distribution and hardware.

COMMON QUESTIONS

Good to know.

Does Sysfix work on Windows or macOS?

No. Sysfix is currently a Linux system diagnostics and maintenance application. Its commands and integrations rely on Linux facilities.

Do I need an AI model to use Sysfix?

No. Core diagnostic commands work without an AI model. Fyxa's local AI assistance requires Ollama and a compatible model.

Does Sysfix automatically change system settings?

The current stabilization build disables autonomous repair execution. Review proposed actions and their impact before running privileged commands.

Why does a feature say unavailable?

Some features depend on optional tools, root permissions, kernel capabilities, hardware sensors or a particular Linux distribution. An unavailable integration does not mean your system passed that check.

Where can I report a bug or request help?

Visit the Guts & Bolts support page or open the Sysfix issue tracker.

Where can I see the source code?

Sysfix is maintained in the Guts-Bolts/Sysfix GitHub repository.
